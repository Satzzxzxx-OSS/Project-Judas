# FTFT9 custom-player component verification

The player remains a Judas controller using its capsule only for collision queries. A per-step `PlayerFluidSample` supplies immersion, liquid density, bulk velocity and acceleration from the production hydrostatic field. Buoyancy acceleration is `-(rho_liquid/rho_player)*immersion*(gravity-fluid_acceleration)`. Orientation/support retain actual gravity as their reference. Swimming uses full look-relative WASD plus gravity-relative Up/Down and the existing jump request; combined intent is normalized and bounded by authored `swimAcceleration*immersion`. Ordinary ground/air control blends out with immersion. Relative linear drag uses an exponential step and cannot overshoot the sampled fluid velocity. No particle reaction acts on the player.

The new `PlayerSwimmingTests.cpp` exercises the actual controller and physics query world with explicitly supplied continuum samples: **89 checks, 2,475 steps, zero failures**. It proves density response, arbitrary gravity, zero neutral drift, common free fall, zero gravity, drag, bounded pitched/diagonal swimming, a bounded submerged floor jump, input disabling and return to dry movement. Invalid field/settings are rejected, not repaired. These are component contracts, not particle-field acceptance; `PlayerFluidIntegrationTests.cpp` separately exercises actual authored particle pools/clouds through `StepPlayedWorld`.
