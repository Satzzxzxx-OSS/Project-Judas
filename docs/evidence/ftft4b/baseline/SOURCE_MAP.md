## Consumers of one endpoint-to-endpoint path

- `src/PlayerController.cpp:359`: support carrying consumes previous/current body transforms. Its presentation at :633/:637 also uses endpoint interpolation.
- `src/PhysicsWorld.cpp:938 GetPreviousTransform`, :948/:955 body boxes, and player sweep above expose/use only two poses (static previous transform is current).
- `src/DynamicBody.cpp:18/:22` presentation mix/slerp, :26 snapshot and :31 physics synchronization; `src/WorldPresentation.cpp` uses these poses for drawing.
- `src/Simulation.cpp:167` constructs previous/current collider inputs; `src/FluidWorld.cpp:107` interpolation and :175 collider preparation consume those endpoints. These files are observed only; no fluid work was performed.

None of these observations authorizes treating teleport/door reset as a kinematic trajectory. Nor does the constant-omega probe establish general torque-free asymmetric-body dynamics. The event-subdivision dependency is prospective: no naive event loop was added or tested as existing production behaviour.
